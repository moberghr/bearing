## Shape

Bearing is a cross-platform **Avalonia desktop** SQL query tool for PostgreSQL, structured as a clean
layered solution (.NET 10, `Bearing.slnx`):

```
Bearing.Core         abstractions + records only — no dependencies
  ↑        ↑      ↑
Bearing.Sql  Bearing.Data  Bearing.Persistence
  (SQL parse/  (Postgres via   (SQLite: query log,
   completion)  Npgsql)         workspace, recents)
        ↑
Bearing.App          Avalonia MVVM shell (ViewModels/Views/Controls/Input/Connections/Results)
        ↑
Bearing.Desktop      thin entry point
```

## Principles observed

1. **Dependency-free core.** `Bearing.Core` contains interfaces (`IDbProvider`, `IProjectStore`,
   `ISessionStore`, `IQueryLog`, `IRecentProjects`, `ISchemaSnapshot`, …) and plain records. No provider,
   UI, or third-party types leak into it. All concrete implementations live in outer projects and are
   injected behind these interfaces.

2. **Strict dependency direction.** `Sql`/`Data`/`Persistence` depend only on `Core`. `App` composes all
   four. `Desktop` depends only on `App`. There are no back-references or sideways references.

3. **Manual composition root.** `App.axaml.cs` news up every implementation (`ProviderRegistry`,
   `JsonProjectStore`, `JsonSessionStore`, `SqliteQueryLog`, `FileRecentProjects`, `MainWindowViewModel`).
   No IoC container is used.

4. **MVVM with logic out of the view.** ViewModels (`CommunityToolkit.Mvvm`) own state and orchestration;
   services under `App/Connections`, `App/Results`, `App/Formatting` own connection lifecycle, result
   shaping, and formatting. Code-behind is limited to visual construction and event wiring.

5. **Pure logic is extracted and unit-tested.** SQL building (`ResultEditModel`, `WriteGuard`,
   `FirstPageLimiter`, `StatementSplitter`), result shaping (`ResultSetBuilder`), and input handling
   (`GestureParser`, `PaletteFilter`, `KeymapDiff`) are stateless and tested without a UI or live DB.

6. **Raw ADO, no ORM.** Postgres access is direct Npgsql; local state is `Microsoft.Data.Sqlite`. Query
   sessions are pooled by (connection Id, database) and protected by leases during long reads.

7. **Skip-safe integration tests.** Postgres-backed tests use `Xunit.SkippableFact` + `BEARING_TEST_PG_*`
   and skip cleanly with no server, so `dotnet test` is green offline.

## ⚠️ Inconsistencies / known debt

- **God objects.** `Controls/ResultView.cs` (~1700), `Views/MainWindow.axaml.cs` (~1600), and
  `ViewModels/MainWindowViewModel.cs` (~1000) concentrate too much responsibility. Partial extraction has
  begun (`Results/ResultSetBuilder`, `Results/ResultEditModel`); the coordinator split (connections/
  execution/tabs/panels out of the VM) and the code-behind overlay-builder split are still pending. See
  `.claude/rules/project-specific.md` §9.1.
- **`Microsoft.Extensions.DependencyInjection` is referenced but unused** as a container — wiring is manual.
- **No secret fallback**: with no OS keyring, passwords aren't stored at all (surfaced to the user, not silent).
- **TLS not enforced** — `sslmode` is opt-in per connection.

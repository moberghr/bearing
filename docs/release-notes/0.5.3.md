Four fixes from using 0.5.2 in anger. The first one is the important one: long queries were being killed
after thirty seconds.

### Long queries are no longer cut off after 30 seconds

A query that ran for more than half a minute failed with `Exception while reading from stream`. That was
Npgsql's default command timeout, which Bearing never set and so never overrode — every query in every
version until now had a thirty-second ceiling.

There is no ceiling now. Running a slow analytical query is the point of the tool, and you can already stop
one whenever you like: press `Esc`, or click the Run button, which turns into a red stop square while a query
is in flight.

A connection can still impose its own limit if you want one — a `CommandTimeout` entry in that connection's
options, in seconds — and the driver overshoots whatever you set by roughly two seconds.

Removing the ceiling would have been reckless on its own, so connections now send a keepalive as well. With
no clock on the query, something has to notice a connection that has actually died, and a keepalive can tell
"the link is gone" apart from "this is taking a while" — which is exactly the distinction a timeout cannot
make.

### And when a query does hit a timeout, it says so

`Exception while reading from stream` describes the driver's plumbing rather than what happened. A timeout now
reads as one, and says the thing with consequences: **the query may still be running on the server.** An
`UPDATE` that appears to have failed this way may well have committed.

### Copy as JSON no longer escapes your data

A copied `timestamptz` arrived as `2026-07-16 14:16:49\u002B00:00` — the `+` of the offset replaced by an
escape sequence. Anything non-ASCII went the same way, so a name with an accent came out as a run of `\uXXXX`.

That was .NET's JSON writer escaping everything that could be unsafe inside an HTML document. Clipboard text
is not markup, so it doesn't need that: a copy now contains `+00:00` and `Čevapčići` as written. Everything
JSON genuinely requires escaping still is, and **Copy as ▸ Table** — the flavour that really is HTML, for
Teams and Outlook — escapes exactly as before.

### Completion stops interrupting inside strings

Typing inside `'…'` no longer opens the suggestion popup. A string literal is data; nothing in your schema or
in SQL's grammar belongs there.

Typing inside `"…"` still completes, deliberately — double quotes are how you name an identifier with a
capital or a space, so that is precisely where a table or column name is wanted.

And keywords no longer crowd out your own tables when they match only by accident. Typing `ete` used to offer
`delete` above everything, because those three letters happen to appear in it in that order; keywords matched
that loosely now sort below every table and column. Keywords you actually started typing are untouched —
`sel` still gives you `select` first, and `gb` still finds `group by`.

### Upgrading

Nothing to do. No settings, projects or keybindings change.

### Known limitations

Unchanged from 0.5.0: the installers are unsigned, so Windows SmartScreen warns on first run; there is no
macOS package; and syntax colouring is verified by eye rather than by tests.

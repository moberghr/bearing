The connections panel grew up: folders, renaming, duplication, and an importer that reads your DBeaver
workspace. Plus release notes you can read without leaving the app.

### Connections

- **Folders.** Group connections however you already think about them — by client, by product, by
  environment tier — and nest them as deep as you like. Drag a connection onto a folder to file it, drag a
  folder into another to reorganise, drop anywhere else to move something back to the top level. Deleting a
  folder keeps the connections in it: they move up one level, never away. Which folders you have open is
  remembered per project (#80).
- **A filter box.** Narrows the panel by name, `host:port`, database, user or environment label — so finding
  which of four similarly named connections is the one on 5434 no longer means reading every row.
- **Rename in place.** Renaming a connection or a folder is an inline edit on the row, not a trip through
  the settings dialog. Renaming no longer collapses the tree or discards the databases it had loaded, either
  (#56).
- **Duplicate,** for when a new connection differs from an existing one by a database name. The copy lands
  beside its source, keeps its environment colour and write guard, and carries the saved password across, so
  it connects without a retype.
- **Copy and paste.** Copy a connection to the clipboard as readable JSON and paste it back — into another
  project, or into a message to a colleague who can paste it into their own Bearing. **No password and no
  identity travel with it**; the recipient supplies their own credential.
- **New script using this connection,** on the right-click menu. `Ctrl+N` also notices where you are: with a
  connection selected in the panel it opens a script against that one, and behaves exactly as before
  everywhere else (#57).

### Import from DBeaver

**`Import connections ▸ From DBeaver…`** — on the connections panel's right-click menu, in the File menu,
and on the panel's empty state. Bearing finds your DBeaver workspaces itself, or you can point it at a
`data-sources.json`.

Your folders come across with your connections, along with each connection's environment type and its
data-change confirmation setting, which map onto Bearing's environment colours and its write guard. A review
step shows exactly what will be imported before anything is written, and names what was skipped and why —
non-PostgreSQL connections are listed rather than silently dropped. Re-importing later updates what you
already have instead of duplicating it (#72).

**Passwords are not imported, and neither are user names.** DBeaver keeps both in an encrypted file of its
own, and reaching into another application's credential store is not something Bearing will do quietly.
Imported connections ask for a password when you first connect, and it goes to your OS keychain from there.

### Elsewhere

- **What's New, in the app.** `Help ▸ What's New` shows the release history; the update strip links to the
  notes for the version it is offering, so you can see what an update contains before deciding to restart;
  and the first launch after an update opens them once. This page is that dialog (#58).
- **Ports are shown.** A server reads as `localhost:5434` rather than `localhost` in the schema tree, the
  connection tooltip and the password prompt — so two Postgres instances on one machine stop looking
  identical (#79).
- **Connection state is a distinct mark.** The environment colour and the connected/disconnected state used
  to both read as coloured dots, so a green "staging" tag looked like "connected". State is now its own
  glyph, carried in its shape rather than only its colour, and the environment is a wash across the row
  (#45).
- **Switching database keeps the connection.** Pointing a tab at another database on the same server used to
  throw away the working connection and build a new one. Each database now has its own pool, so switching
  back and forth reuses both, and the connection indicator reports the server rather than one database's
  pool (#54).

### Fixed

- Editing a connection no longer discards its `sslmode` and `search_path` options. The dialog rebuilt the
  connection from its visible fields, so anything not shown there was dropped on save.
- The schema tree no longer collapses every time a connection is edited.

### Upgrading

Nothing to do — projects from 0.3.0 open unchanged, and the new folder fields are simply absent until you
create a folder. A project saved by 0.4.0 still opens in 0.3.0, without its folders.

### Known limitations

- The installers are **unsigned**, so Windows SmartScreen warns on first run.
- **No macOS package.** Velopack needs `codesign` / `xcrun` / `productbuild`, so a signed `.app` requires a
  Mac and an Apple Developer ID.
- The DBeaver importer reads **PostgreSQL connections only**. Other drivers in the same workspace are listed
  as skipped rather than imported.

Thirty-one issues, and most of them are the kind you notice within a minute of using the app: the results
grid selects and navigates like a spreadsheet, the editor closes your quotes and shows its fold margin, tabs
pin and scroll, and the schema tree finally tells you what a table is made of and how big it is. Bearing also
runs with **no database at all** now, so you can see all of it before you have a connection to try it on.

### The results grid

- **Click the corner to select everything.** The empty box above the row numbers selects the whole result, as
  it does in every spreadsheet. A right-click there opens the menu over what you already had selected instead
  of quietly expanding it to every row (#55).
- **Tab moves between fields.** Tab and Shift+Tab step across the row in reading order, wrapping to the next
  row at each edge, so a row can be reviewed or edited without reaching for the mouse. It stops at the two
  ends of the result rather than cycling (#10).
- **Columns stop clipping.** A column sized to exactly its widest value rendered `110122` as `1101…`. Widths
  now come from text that was actually measured, with the padding the design asked for (#73, #30).
- **NULL looks like NULL everywhere.** In a foreign-key column it rendered as ordinary bright text, because
  the three kinds of cell each built their own label. They share one now, so a NULL is dimmed italic wherever
  it appears (#61).
- **Editing a cell no longer scrolls it away.** Committing an inline edit could jump the viewport somewhere
  else entirely, which meant losing your place in the middle of a row-by-row correction (#60).
- **Stacked results are resizable.** Several result sets from one run each used to be hard-capped at 360px.
  They now divide the pane proportionally, and every seam between them is a divider you can drag — including
  the one between the editor and the results (#81).

### Timestamps, with their zone

`timestamptz` values are instants, and Bearing used to print them with no offset at all — so a value was
unreadable without knowing which zone the server had decided to render it in.

- Timestamps now show their offset, and **Settings ▸ Results ▸ Show timestamps in** chooses the zone: your
  system zone, UTC, or any zone you name. Editing one round-trips correctly — a UTC 15:00 shown as
  `18:00+03:00` and edited writes back UTC.
- A `timestamp without time zone` has no zone to convert from, so it is left exactly as stored and its column
  carries a small badge saying so. The badge is on the header, never in the cell text — cell text travels into
  your clipboard, your exports and your edits, and an invented `+00:00` in any of those would be worse than
  no information at all (#77).

### Export a whole run to one workbook

**Export run** writes every result set from a run into one `.xlsx`, a sheet per result, named from the
query's table where there is one and numbered where two would collide. Previously an export was one result at
a time, so a five-statement run meant five files (#12).

### The editor

- **Quotes and brackets auto-close,** typing over the closer instead of doubling it, and Enter escapes the
  pair rather than splitting it. Selecting text and typing a quote wraps the selection (#70).
- **The fold margin is visible.** Statement folding was implemented end to end and drew no markers, so
  nothing could be folded by mouse. The gutter is there now, coloured with the rest of the chrome (#74).
- **Folding no longer crashes.** Clicking in the editor after a fold threw *Trying to build visual line from
  collapsed line*. The caret is now kept out of collapsed regions on every edit, not only on the fold
  commands, and a fold never survives into a swapped buffer (#82).
- **Statement keywords are suggested on a fresh line** even when the statement above it has no trailing
  semicolon (#68).
- **An FK join completion inserts the `join` keyword** it was leaving out, so the result is a clause that
  runs (#75).

### Tabs

- **Pin a tab** and it moves to a row of its own, above the rest, and stays there across a restart (#67).
- **A chevron shows the tabs that don't fit.** With many tabs open, the ones past the right edge were simply
  unreachable — laid out and then clipped, with nothing to scroll them. A `» 4` chevron now appears beside the
  `+` button whenever tabs are off the edge, carrying the count, and clicking it opens a filterable list of
  **every** open tab — pinned row first, then the rest, each with its folder so two files of the same name are
  tellable apart. `Ctrl+E` opens the same list from the keyboard — Eclipse's gesture for it, so the reflex carries over from
  DBeaver.
  Long tab names are also capped and ellipsized now: one long filename used to take its full natural width and
  push everything else off the strip (#65).
- **Middle-click closes a tab,** including a middle-click that lands on the ✕ itself (#66).
- **Closing a tab selects its neighbour** rather than jumping to the first tab (#87), and **a new tab takes
  keyboard focus** so you can start typing without clicking into the editor first (#88).

### The schema tree

- **A table's structure, not just its columns.** Expanding a table now shows its primary key, unique and
  check constraints, foreign keys, the tables that reference it, its indexes and its triggers — with
  `INCLUDE` columns, partial-index predicates and constraint definitions rendered as Postgres reports them
  (#46).
- **Sizes on disk.** Tables, indexes and databases show their size, with the table figure split into heap and
  index where that is the interesting part. A never-analysed table says so rather than reporting a row
  estimate of -1 (#76).
- **Tighter rows.** Both navigator trees inherited Fluent's stock item metrics, which are sized as touch
  targets — so an expanded table spread a handful of column names down the panel and the tree read as sparse
  rather than scannable. A row is one line of text beside a small glyph and is now sized like one. The
  per-level indent is unchanged: it comes out of the control template rather than off a property (#71).

### Font size, everywhere it was missing

Text size used to be settable for the editor and the cell inspector only — so making things bigger left the
results grid, the panels, the tab strip and the status bar exactly as they were. Each surface now has a dial
of its own:

| Setting | Covers |
|---|---|
| **Editor ▸ Font size** | the SQL editor (Ctrl+wheel still zooms one tab on top of it) |
| **Results ▸ Result grid font size** | values and column headers; row height follows, so a bigger font gives taller rows rather than clipped ones |
| **Results ▸ Cell inspector font size** | the inspector pane |
| **General ▸ Interface font size** | panels, tab strip, status bar and the result meta rows — captions stay proportionally smaller, so the hierarchy survives a bigger setting |

The grid and the interface dials are independent on purpose: wanting bigger data is not the same as wanting
bigger furniture. Stock controls — buttons, text boxes — keep the theme's own size (#52).

### Transport security is a setting

`sslmode` used to be an entry in the connection's options bag — invisible in the dialog, and able to be
overridden by a shared `project.json`. TLS is now a first-class field on the connection with five explicit
modes, and the dialog names *which* guarantee the chosen mode is missing rather than reducing encryption to a
checkbox.

- A **new** connection requires encryption unless the host is loopback. Existing projects keep the behaviour
  they had.
- `sslmode` and the other transport keywords are **reserved** in the options bag, so a project file cannot
  outrank the field — the same rule that already stopped a stray `Password` key beating your keychain (#23).

### Query-log privacy

- The log's files are narrowed to their owner on startup, **sidecars included** — the `-wal` file holds the
  newest entries, so hardening the database alone left them readable. A no-op on Windows, where
  `%LOCALAPPDATA%` is already restricted.
- **Optional literal stripping.** *Settings ▸ History ▸ Replace values in logged SQL with placeholders*
  rewrites string, numeric and dollar-quoted literals before an entry is written — the history file otherwise
  holds every value you typed into a WHERE clause, in plain text, until retention prunes it. Off by default,
  and deliberately: a redacted statement can't be re-run from the history panel, and silently rewriting your
  own record of what you did isn't ours to decide. When it is on, redaction happens at the boundary, so the
  stored row, the event and the history panel all agree (#22).

Encryption at rest is still **not** implemented, and the reason is in the docs rather than a backlog: it needs
a key you supply, and a key kept next to the file it encrypts protects nobody.

### Demo mode — Bearing with no database

`bearing --demo`, or **Explore demo data** on the connections panel's empty state, starts a whole session
served from a fixed catalog with no database anywhere: real result sets, a real schema tree, foreign-key
navigation, primary-key badges, inline editing and the write-guard confirmation, all from fixtures.

It is decided once at startup and is process-wide — the demo provider replaces Postgres in the registry
rather than sitting beside it, so it isn't reachable from any ordinary connection flow. Everything it writes
goes to one temp directory that is deleted on exit: no entry in your recent projects, no rows beside your
query history, no keychain call. It ships in Release builds, because evaluating Bearing without a Postgres to
point it at is exactly the case it exists for (#64, #63).

### Fixed

- The history panel refreshes when a query finishes, instead of only on a panel switch or Enter in its search
  box (#78).
- Two intermittent test failures that made the suite fail roughly one run in two are fixed at the cause — one
  a file observer racing its own autosave, the other a second update check firing during startup (#83).

### Under the hood

- **The UI is testable.** `Avalonia.Headless` is wired up, so a claim that only a realized visual can hold —
  a brush on a live cell, a scroll offset after a layout pass, a measured column width, what a keystroke does
  to a control that exists — has somewhere to live. The whole shell runs under it, not just isolated controls
  (#62).
- **`./build/test-db.sh`** provisions the PostgreSQL the integration suites have always named and nothing
  created, loads pagila, and verifies it. A bare `dotnet test` now runs the data-layer suite live with no
  environment variables.

### Upgrading

Nothing to do. Projects from 0.4.0 open unchanged; the new TLS field is absent until you touch it, and a
connection without it keeps the transport behaviour it had. A project saved by 0.5.0 still opens in 0.4.0,
where the TLS field is ignored and pinned tabs come back unpinned.

### Known limitations

- The installers are **unsigned**, so Windows SmartScreen warns on first run.
- **No macOS package.** Velopack needs `codesign` / `xcrun` / `productbuild`, so a signed `.app` requires a
  Mac and an Apple Developer ID.
- **Syntax colouring is verified by eye, not by tests.** The TextMate grammar colours a line as it is drawn,
  which resists a deterministic assertion; a colouring suite was written and dropped rather than shipped
  flaky.
- Column selection on a partially fetched result covers the **loaded** rows only, and says so in the status
  bar. Fetch the rest first if you need the whole column.

One change, in the surface you spend the most time reading: numbers in the result grid are grouped.

### Numbers read as magnitudes

A numeric cell draws **1,234,567.89** rather than `1234567.89`. The point is the glance — whether a figure is
a hundred thousand or a million is now a shape rather than something you count digits to work out.

**What you copy is not what you see, and that is deliberate.** Copies, CSV and xlsx exports, Copy as ▸ SQL,
the generated DML and the in-cell editor all carry the ungrouped value. The separator lives in the cell and
nowhere else, because a number that has been made easier to read must not become a number that reads back
differently: parsing `1,234` is ambiguous — in a comma-decimal locale it means 1.234 — and a value silently
multiplied by a thousand on its way into an `UPDATE` is a much worse problem than an unreadable column.
Excel still gets real numbers that sum, not text.

**The separator is always a comma, whatever your machine's locale says.** The decimal point in this grid is
already fixed — 0.2.0 made it so, after CSV exports emitted `9,5` on comma-decimal locales and re-imported as
95 — and mixing the two conventions in one number gives `1.234.567.89`, which is nothing at all. One
convention for both halves, or neither is readable.

It applies to every numeric column, identifiers included, so an `id` of 110122 draws `110,122` too. Turn the
whole thing off in **Settings ▸ Results ▸ Group digits in numeric columns** if you would rather it did not.

**The quick-stats bar now agrees with the cells above it.** It had always grouped by the machine's locale, so
on a comma-decimal machine it read `1.234,5` directly underneath cells reading `1234.5` — two conventions in
one glance. It follows the grid, and the setting.

### A numeric cell you have typed something wrong into says so

Type a value an editable numeric column cannot take — a word, or a number in a form that cannot be read
unambiguously — and the cell is drawn amber instead of waiting until you save to tell you. Previously the
only notice was the server rejecting the batch.

This arrived with the grouping and is the reason it is worth calling out: in a column drawing `1,234`,
typing back the `1,234` you just read produces a value that is *refused*, and which then looked exactly like
one that was accepted. Accepting it instead was not an option — see above for what `1,234` means elsewhere in
the world.

### Upgrading

Nothing to do, and nothing about your data or your exports changes. If you would rather see plain digits,
the setting is in **Settings ▸ Results**.

### Known limitations

Unchanged: the installers are unsigned, so Windows SmartScreen warns on first run; there is no macOS
package; and syntax colouring is verified by eye rather than by tests.

A `numeric` value too large to fit a `decimal` is drawn ungrouped, since it does not arrive as one of the
types the grid treats as numeric.

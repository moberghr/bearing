Bearing runs on macOS, and installs with one line.

### `brew install --cask --no-quarantine moberghr/bearing/bearing`

There is a macOS build now — a real `Bearing.app` in `/Applications`, Apple Silicon, with the same
self-updating behaviour Windows and Linux already had. It checks once per launch, downloads in the
background, and offers a restart; `brew upgrade` is not part of that path and never needs running.

The `--no-quarantine` is not decoration, and it is worth saying why rather than letting you discover it.
The app is not yet signed with an Apple Developer ID. macOS marks anything downloaded as quarantined and
refuses to open an unsigned bundle carrying that mark — with the message "Bearing is damaged and can't be
opened", which is Gatekeeper's way of describing a signature it does not like, not a corrupt download. The
flag says "I fetched this deliberately". When a certificate exists the flag goes away and nothing else
about the install changes.

Prefer not to use Homebrew? `BearingSql-osx-Setup.pkg` on the release page installs the same app.

### Also in this release

- The release pipeline's upload check was verifying the wrong file for the Linux channel — it looked for a
  package name only the Windows build produces, and since both land on one release, a Linux upload that
  failed would have been reported as a success. It now checks the package its own channel actually writes.
- A failing test run left the release published with nothing attached to it. Withdrawing a broken release
  back to draft now covers the test job too, not only the build — and actually manages to do it, which
  0.10.2 did not.

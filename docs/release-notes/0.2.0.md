First packaged release. Bearing now installs and updates itself (#20).

### New

- **Installers.** Windows gets a per-user `BearingSql-win-Setup.exe` — no admin rights, Start Menu entry,
  installs to `%LOCALAPPDATA%\BearingSql`. Linux gets a self-updating `BearingSql.AppImage`.
- **Automatic updates.** The app checks the release feed once per launch, downloads a newer version in the
  background, and then waits: installing only happens when you choose to restart, so an update never
  interrupts a running query or discards an unsaved buffer. `Help ▸ Check for Updates…` does the same on
  demand.
- **Updates are deltas.** After this release, an update downloads only the files that changed rather than the
  full ~65 MB package.
- **A setting to turn it off.** *Settings ▸ General ▸ Download updates automatically*. Off, nothing is
  checked or downloaded in the background; the menu item still works.

### Your data is not in the install directory

Settings, projects, the query log and recent-project list stay where they were — `%APPDATA%\bearing` and
`%LOCALAPPDATA%\bearing` — and are untouched by an install, an update or an uninstall. Connection passwords
remain in the OS credential store.

### Install

- **Windows** — `BearingSql-win-Setup.exe` (per-user, no admin). Updates itself from here on.
- **Linux** — `BearingSql.AppImage`, `chmod +x` and run. Updates itself in place.

The single-file `.tar.gz` / `.zip` archives from `build/release.sh` still exist for portable use; they have
no update path.

### Known limitations

- The installers are **unsigned**, so Windows SmartScreen warns on first run.
- **No macOS package.** Velopack needs `codesign` / `xcrun` / `productbuild`, so a signed `.app` requires a
  Mac and an Apple Developer ID.
- Releases are still built and published from a working copy — CI is #24.

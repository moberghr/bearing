**The `bearing` command, tuned by the first agent to use it for real.** Four things it had to guess at, now
answered by the command itself.

### A missing connection and an unexposed one are no longer the same answer

`bearing connections` used to list the exposed connections and nothing else, so an agent that found only
`prod` could not tell whether `stage` did not exist or simply had not been exposed. It now also names the
project's connections that are **not** exposed — by name only, with no engine, environment or address — so
the agent can say "ask the owner to expose `stage`" instead of guessing.

```console
$ bearing connections --table
project: Payments (C:\work\payments)
name  engine      access     available  environment
----  ----------  ---------  ---------  -----------
prod  PostgreSQL  read-only  true       production
not exposed: stage, dev
```

This discloses nothing new: naming `stage` directly already answered "'stage' is not exposed", and anything
that can run the command can read the same `project.json`.

### It says which project it read

Without `--project`, `bearing` reads the project most recently opened in Bearing — which a person knows and
an agent cannot see. `connections` now names it (`project` in the JSON), so an agent can tell when it is
looking in the wrong place and pass `--project` from then on.

### `--tsv`: output for an agent to read rather than parse

Agents turned out to prefer `--table` over the JSON for small results — it is shorter and easier to read.
`--tsv` is that same layout, tab-separated: compact, and unlike `--table` unambiguous. A tab, newline or
backslash inside a value is escaped (`\t` `\n` `\\`) and a null is `\N`, so an empty string and a null no
longer print alike. JSON remains the default and the stable contract for scripts.

### Several statements in one query

`bearing --help` now says what happens: they run in order and each is its own result set — one entry in the
JSON `results`, or one grid after another with a blank line between. If any of them fails, only the error is
printed.

### Fixed

- **Array and hstore columns printed a .NET type name under `--table`** —
  ``System.Collections.Generic.List`1[System.Object]`` in every row of `select special_features from film`.
  They print as compact JSON now (`["Trailers","Deleted Scenes"]`), in both `--table` and `--tsv`. The JSON
  output was never affected.
- The command descriptions in `bearing --help` were misaligned; they line up now.

### Upgrading

Nothing to do. The JSON output only gains fields (`project`, `not_exposed`); nothing is renamed or removed.
The app itself is unchanged.

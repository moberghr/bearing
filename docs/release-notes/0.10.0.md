Three small things in the way the app answers you: submenus that open when you point at them, the schema
tree's shape as a button rather than a row, and an import that brings the passwords with it.

### Submenus open when you point at them

Hovering **Copy as ▸** in the results menu used to sit still for 400 ms before the submenu appeared — long
enough that pointing at it read as the app not responding. It opens on the frame the pointer arrives, and so
does every other submenu: Export ▸, the schema tree's Import connections ▸, the menu bar.

The delay was one value for two behaviours, and removing it is a trade rather than a free win: it also timed
the *close* of a neighbouring submenu, so sweeping the pointer down a menu past Copy as now flashes its
submenu open and shut on the way past, where the wait used to swallow the sweep.

### The schema tree's shape is a button, not a row

**Simple** and **Full** were a pair of pills on their own row under CONNECTIONS. They are now one icon button
beside the folder, showing the shape in force — flat rows for Simple, stepped rows for Full — with a tooltip
that names it and says what a click switches to. The panel gets the row back, which on a 262px pane is worth
having.

Nothing about the two shapes themselves changed, and the setting is still in **Settings ▸ Connections**; the
button and the setting are two ends of the same preference.

### Importing from an installed Bearing, from where you are standing

*Dev builds only — this is the path that copies the installed app's connections into a build running from
source, and it cannot appear in an installation.*

It was reachable from exactly one place: right-clicking empty space in the schema tree. On a first run the
tree is empty, which is precisely when nobody thinks to right-click it. It is now also on the empty state's
**Import connections…** button and in **File ▸ Import connections**, all three gated on the same check.

**Saved passwords now come with the connections.** They live in the OS credential store under a key whose
first segment is the profile, so an imported connection used to find nothing under its own profile and prompt
on every connect. The copy is a read under one key and a write under another — same user, same machine, same
credential store you can already open yourself.

What that costs is worth stating plainly: the profile isolation used to mean a build from source could not
reach a production server without someone typing the password, and it no longer does. The copy persists, and
later dev builds read it.

Two things it will not do. A connection set to prompt every time — or to use an Entra token — is left alone,
because nothing would ever read a password stored for it and writing one would leave a real credential in the
keychain that no code path touches. And when a copy writes over a password that profile already held, the
status line says how many, since the value it replaced cannot be got back.

**If you upgraded to 1.1.0, your Start Menu shortcut was left pointing at the wrong file.** This release
repairs it. That is the whole of it.

### What happened

1.1.0 gave the name `bearing` to the new command line, and renamed the window's executable to `bearing-app`
so the two could live in one directory. Velopack writes the Start Menu shortcut when Bearing is *installed*,
aimed straight at the executable it was told about then — and an update swaps the files without revisiting
that shortcut. There is no updater command that would.

So every machine upgrading from 1.0.x kept a shortcut aimed at `bearing.exe`, which after 1.1.0 is the
command rather than the window.

Bearing still opened. The command with no arguments launches the window — that is deliberately its
behaviour, and it is what turned this from a broken shortcut into a cosmetic one — but it is a console
program, so a console window flashed on the way through.

The repair runs from the installer's own hooks, once, and does nothing on a machine that never had the old
shortcut. It rewrites a shortcut only when the target sits in Bearing's install directory *and* is named
`bearing.exe`, so a shortcut of yours that happens to point at some other `bearing.exe` is left alone.

**A fresh install of 1.1.0 was never affected** — its shortcut was written with the new name from the start.

### If you would rather not wait

Nothing is broken and there is nothing you need to do. If the console flash bothers you before you next
update, re-running the setup you downloaded recreates the shortcut, or you can repoint it at
`bearing-app.exe` by hand.

### Upgrading

Nothing to do. No settings, projects, connections or keybindings change, and the `bearing` command is
unchanged.

### Known limitations

Unchanged from 1.1.0.
